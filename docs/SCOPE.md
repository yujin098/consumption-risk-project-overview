# 공개 범위와 해석의 한계

[전체 안내](../README.md)

## 어떤 자료를 확인할 수 있나?

| 구분 | 공개 범위 | 재현 가능 범위 |
| --- | --- | --- |
| 가상데이터 예제 | 입력 생성·품질점검·점수·기준 비교·계산 보고서 | 공개 코드로 실행 가능 |
| 실제 분석 | 접근 과정과 일부 요약 수치 | 원본·상세 결과표가 없어 실제 수치 재현은 불가 |
| CPI·K-means | 보조 함수와 인공 입력 테스트 | 함수 동작 확인 가능, 가상 실행에서는 미사용 |
| 실제 군집·규칙 비교 | 판단 요약 | 상세 검증 코드·입력 결과표는 로컬 보관 |

공개 범위는 프로젝트 설명과 핵심 계산·가상 예제로 정했다. 원본 데이터와 상세 결과표,
발표자료는 포함하지 않는다. 이는 현재 저장소 구성에 대한 설명이며,
BC카드가 해당 문서나 수치의 삭제를 요청했다는 뜻은 아니다.

가상 실행에는 원본 데이터·외부 API·CPI 파일이 필요하지 않다. 가상 결과는 실제 분포를
모사하거나 실제 분석 수치·금융 예측력을 검증한 결과가 아니다.

## 공개 예제의 품질점검 기준

- 분석 기간을 월 시작일의 연속 목록으로 명시한다. 전체 입력에서 한 달이 통째로 빠져도 탐지한다.
- 관측된 모든 지역·업종을 결과에 남긴다. 입력에 한 번도 등장하지 않은 조합은 별도 전체 목록이 있어야 알 수 있다.
- 같은 월·지역·성별·연령대·업종 키가 중복되면 해당 지역·업종 전체를 보류한다. 임의 합산이나 자동 삭제를 하지 않는다.
- 유한한 양수 금액, 양의 정수 건수, 유효한 연령코드 1~6과 지역 간에도 일관된 업종명을 요구한다.
  법인·연령 미분류 행까지 일반화한 전처리는 이 공개 예제의 범위에 포함하지 않는다.
- 기간 누락·중복·유효 값 문제 대상은 비교 기준 합계에서도 제외한다.
  저거래량 대상은 비교 기준 합계에는 포함하지만 해당 설정의 점수는 유보한다.
- 전체 대상이 제외되면 품질 결과만 남기고 점수·개별 계산 예제를 만들지 않는다.

이것은 공개 `run_analysis` 흐름의 처리다. 하위 함수만 개별 호출할 때 같은 검증이
자동 적용되는 것은 아니다. 키·날짜 등 입력 형식 오류는 정규화 단계에서 실행을 중단할 수 있다.

## 기준 비교를 어떻게 읽나?

기본 가중치와 동일 가중치, 월 최소 거래량 50·100·200건을 조합한다.
기본 실행에서 모든 비교의 기준은 `baseline_100`이며 기본 상위 3개와 각 설정의 상위 3개를 대조한다.
함수 직접 호출 시 첫 거래량 기준과 `top_n`으로 이를 바꿀 수 있다.
대상이 부족하면 가능한 수만 선택하고, 기준 설정에 대상이 없으면 유지율은 비워 둔다.

동점 점수에는 같은 최상위 순위를 부여한다. 상위 목록의 동점 선택은 지역·업종 키 순서로
고정한다. 순위 변화 평균은 두 설정에서 모두 산출된 대상에 한해 계산한다.
진입·이탈 대상이 빠지므로 대상 수와 상위 목록 변화도 함께 봐야 한다.

거래량 기준을 바꾸면 산출 대상과 백분위 기준 분포가 함께 바뀐다.
가중치 비교는 같은 거래량 기준 안에서 정규화 값의 비중만 바꾼다.
50·100·200건과 가중치는 비교용 설정이며 최적 기준으로 검증되지 않았다.

## 남아 있는 분석 한계

1. CSDI와 하위 코드의 `risk_tier`는 분석상 점수·분류다. 부도확률·신용등급이나 자동 여신 결정이 아니다.
2. 상대 비교는 원인 추정이나 완전한 계절성 제거가 아니다. 절대 금액이 증가해도 상대점수는 높을 수 있다.
3. CPI 함수는 전국 종합 지수로 금액을 보정하며 구매 수량을 복원하지 않는다. CSDI 산식에는 `real_amount`를 사용하지 않는다.
4. 백분위 점수는 비교 집단에 의존한다. 작은 변화나 동점이 많아도 서로 다른 점수가 생길 수 있다.
5. 두 달만 관측된 경우 변동성 계산에 정보가 부족하다. 기존 점수 함수의 정규화 값 결측은 0.5,
   동반부진 비율 결측은 0으로 대체하므로 충분한 관측 기간과 별도 해석이 필요하다.
6. 테스트는 인공 입력의 계산·경계조건·출력을 확인한다. 실제 금융 성과나 운영 적합성의 검증이 아니다.

기간을 바꿔도 순위가 안정적인지, 가중치·거래량 기준을 어떤 근거로 선택할지,
실제 점검 업무에 도움이 되는지는 추가 검증 과제다.

## 본인 역할과 AI 활용

본인은 직무 관점의 목적을 정하고 과장된 주장을 제외하며, 분석의 선택 이유가 드러나도록
방향을 조정했다. 코드 작성·실행·검증 및 문서 초안에는 AI가 사용됐다.
전체 코드를 직접 개발한 경험으로 소개하지 않으며, 직접 검토·수정한 범위는
[계산과 질문](EXPLAIN_IT.md)에 기록한다.

대회 제출 완료·수상·기관 도입을 주장하지 않는다. 공개 예제를 추가했다고 해서
과거 데이터 처리나 약정 관련 판단이 자동으로 해결되는 것은 아니다.
