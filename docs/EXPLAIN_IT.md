# 계산을 이해하고 설명하기

[전체 안내](../README.md) · [가상 결과 예시](DEMO_RESULTS.md)

아래 질문은 공개 코드와 가상자료로 확인하는 연습이다.

## 1. 왜 금액과 건수를 나누는가?

금액 100,000원이 유지되고 건수가 10건에서 8건이 되면 건당 금액은
10,000원에서 12,500원이 된다. 금액 변화는 0%, 건수는 −20%, 건당 금액은 +25%다.
결제건수는 고객 수가 아니므로 고객 2명이 이탈했다고 말할 수 없다.

확인: [features.py](../src/features.py)의 `build_region_industry_month`.

## 2. 비교 방식이 왜 두 가지인가?

지역 금액이 20%, 비교 집단이 10% 증가했다면 변화율 차이는 10%p다.
성장배율 비율은 `1.2 / 1.1 - 1`, 약 9.09%다.

월별 `relative_amount_mom`은 차이를, 기간 비교와 이중 비교는 성장배율 비율을 사용한다.
같은 정의로 읽어야 한다. [가상 예시](DEMO_RESULTS.md)에서는 절대 금액이 늘어도
상대적으로 약할 수 있는 경우를 볼 수 있다.

## 3. 제외됐으면 안전한가?

아니다. 점수를 계산할 근거가 부족하거나 입력 점검이 필요하다는 뜻이다.
`quality_report.csv`에서 저거래량·기간 누락·중복을 구분하고,
`synthetic_panel_scores.csv`에서 이 대상의 점수가 비어 있는지 확인한다.

확인: [analysis_workflow.py](../src/analysis_workflow.py)의 `assess_quality`.

## 4. 왜 기준을 바꿔 보는가?

가중치는 각 신호를 얼마나 반영할지 정하고, 거래량 기준은 누구에게 점수를 매길지 정한다.
거래량 기준을 바꾸면 백분위의 비교 대상도 바뀐다. `sensitivity_comparison.csv`에서
대상 수와 순위 변화를 함께 읽고, 목록이 유지돼도 예측력이 증명된 것은 아니라는 점을 설명한다.

확인: [analysis_workflow.py](../src/analysis_workflow.py)의 `run_analysis`.

## 5. 최종 점수는 어떻게 나오는가?

`REPORT.md`의 개별 예제에서 원래 금액·건수, 상대변화, 정규화 값, 가중치를 차례로 읽는다.
`walkthrough_contributions.csv`의 기여도를 합하면 해당 대상의 점수가 나와야 한다.
백분위는 한 대상만으로 구할 수 없으므로 전체 대상의 `scenario_scores.csv`도 함께 확인한다.
