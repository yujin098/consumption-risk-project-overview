## 어떤 문제를 다루는가

BC카드 소비데이터 활용 공모전을 준비하며 다음 질문에서 시작했습니다.

> 소비 흐름이 약해지는 곳을 찾아, 담당자가 먼저 확인할 대상을 정리할 수 있을까?

단순히 감소한 지역을 나열하기보다, 어떤 변화가 있었고 무엇을 더 확인해야 하는지
설명하는 것을 목표로 했습니다. 여신전략·신용정책·리스크기획·리스크관리 관점에서
제한된 자료를 판단에 연결할 때 필요한 기준을 탐색했습니다.

## 왜 범위를 좁혔는가

초기에는 소비 변화와 여신 위험을 연결하는 넓은 구상을 검토했습니다.
하지만 제공 자료는 개별 차주의 상환능력이나 연체 발생을 확인하는 자료가 아닙니다.
그래서 목표를 **지역·업종의 소비 약화를 살펴보고 추가 점검 순서를 제안하는 것**으로 좁혔습니다.

소비 감소와 부실을 동일시하지 않고, 관측된 변화와 추가로 필요한 정보를 구분하는 것이
이 프로젝트의 출발점입니다.

## 어떻게 접근했는가

| 단계 | 질문 | 처리 |
| --- | --- | --- |
| 품질점검 | 비교할 수 있는 자료인가? | 중복·기간 누락·거래량 확인과 제외 이유 기록 |
| 변화 계산 | 금액과 거래 빈도가 어떻게 달라졌나? | 금액·건수·건당 금액 분리 |
| 상대 비교 | 공통 흐름보다 더 약해졌나? | 전국 동일 업종·지역 전체와 비교 |
| 점수 정리 | 어디부터 확인할 것인가? | 다섯 신호를 CSDI로 정리 |
| 기준 비교 | 설정을 바꾸면 판단이 얼마나 달라지나? | 가중치·최소 거래량별 대상과 순위 비교 |

실제 자료를 살펴본 과정과 이후 공개 가상 예제의 보완은 구분합니다.
단계별 구현과 실제 요약 결과는 [분석 과정](ANALYSIS_STORY.md), 지금 실행할 수 있는 결과는
[가상데이터 결과 예시](DEMO_RESULTS.md)에서 확인할 수 있습니다.

## 본인 역할

본인은 직무 관점의 활용 목적을 정하고, 과장된 주장을 제외하도록 요청했으며,
분석 과정과 선택 이유가 드러나도록 방향을 조정했습니다. 코드 작성·실행과 문서 작성에는
AI의 지원을 받았습니다. 직접 검토하거나 수정한 경험은 확인한 범위에 한해서 설명합니다.

이 프로젝트는 대회 제출 완료·수상·금융기관 도입 실적을 주장하지 않습니다.
세부 범위는 [공개 범위와 한계](SCOPE.md)에 정리했습니다.
